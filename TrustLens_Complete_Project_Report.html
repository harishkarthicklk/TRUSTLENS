1. Executive Summary & System Overview
TrustLens is an end-to-end, schema-agnostic forensic data auditing pipeline designed to automate risk
scoring, anomaly detection, and executive report synthesis. Enterprise data auditing traditionally suffers
from two primary limitations: rigid, hand-crafted SQL/Excel rule sets that fail to detect non-linear data
corruption, or black-box unsupervised machine learning models (such as Isolation Forests) that output
abstract decision scores without actionable business context.
To solve this dual challenge, TrustLens combines Autonomous Large Language Model (LLM) Inference
(powered locally by Ollama Qwen3:8b) with a 9-module deterministic forensic rule engine. The system
ingests raw CSV/XLSX files, dynamically infers domain contexts, selects specialized statistical tests,
computes standardized risk metrics (0–100 scale), and synthesizes decision-ready audit reports.

2. High-Level 5-Phase Pipeline Architecture
The TrustLens backend executes through five distinct, deterministic operational phases:
Phase 1: Ingestion & Sanitization (preprocessing.py & main.py)
Endpoint Reception: Validates uploaded .csv or .xlsx files via API endpoints.
Schema Sanitization: Strips header whitespace and converts string-encoded monetary/percentage fields
(e.g., '$1,250.50', '12%') to floats via regex parsing.
Missingness & Duplicate Tagging: Full-row duplicates are flagged via FLAG_IS_DUPLICATE_ROW without
dropping rows. Missing values in numeric columns receive a temporary sentinel (-99999) to preserve
explicit missingness metadata.
Phase 2: Autonomous LLM Discovery (discovery.py)
Schema Sampling: Samples top 1,000 rows and extracts key data structures.
Dynamic Inference: Sends metadata JSON to local Ollama (qwen3:8b) via HTTP POST. Ollama classifies
the industry domain (e.g., E-Commerce Retail) and selects 2 to 4 forensic modules directly from
FORENSIC_TEST_POOL.
Fallback Execution: Built-in schema rules handle module selection if LLM response exceeds 300s.
Phase 3: Dynamic Feature Selection & Unsupervised ML (feature_selector.py & scoring.py)
LLM Feature Selection: Ollama evaluates features on a 0.0 to 1.0 relevance scale; features scoring ≥ 0.5
are retained while generic noise (IDs, zip codes) is excluded.
Safe Imputation: Sentinel values (-99999) are replaced with column medians.
Isolation Forest Fitting: IsolationForest (100 trees, contamination=0.10) fits on feature matrix X.
Continuous path scores are mapped to Score 1 (0–100 scale). Records with Score 1 ≥ 50.0 are flagged
(PHASE3_FLAGGED = True).
Phase 4: Targeted Forensic Rule Execution (forensics.py)
Modular Execution: Executes selected algorithms from the 9-test pool against dataset features.
Score 2 Calculation: Each test outputs a risk score (0–100). Score 2 is computed as the arithmetic mean
of all executed test scores.
Cross-Phase Overlap Resolution: Resolves Overlapping Records (Phase 3 ∩ Phase 4) vs. Newly Surfaced
Records (Phase 4 \ Phase 3).
3
Phase 5: Audit Report Synthesis & PDF Compilation (interpretation.py)
Executive Narrative Prompting: Phase 3/4 metrics, global means, test breakdowns, and sample high-risk
rows are sent to Ollama to synthesize executive findings.
ReportLab PDF Rendering: Builds document elements into global metric summary cards, breakdown
tables, and recommendations, saving to exports/Audit_Report_<filename>.pdf.
3. Comprehensive Mathematical Foundations
3.1 Phase 3: Isolation Forest & Score Normalization
Isolation Forest isolates anomalies by randomly partitioning feature space using decision trees. The path
length h(x) of a record x is normalized against the average path length of an unsuccessful search in a
Binary Search Tree (BST):
BST Path Length Normalization Factor c(n)
c(n) = 2 * (ln(n - 1) + 0.5772156649) - (2 * (n - 1) / n)
Where n is dataset size and 0.5772156649 is Euler's constant. Raw scores s(x,n) = 2^(-E(h(x))/c(n)) are
shifted by offset_ (10th percentile cutoff). TrustLens scales raw scores into continuous Score 1 (0–100
scale):
Score 1_i = 100 * [ 1 - ( (s_raw,i - s_min) / (s_max - s_min + 10^-5) ) ]
3.2 Phase 4: Mathematical Specifications for All 9 Forensic Modules
Phase 4 incorporates 9 standalone statistical and rule-based forensic tests. Each module calculates a
normalized risk score capped at 100.0 to maintain mathematical stability during aggregation.
1. Outlier Detection
Flags rows exceeding 1.5 * IQR statistical bounds across numeric columns.
Formula & Flagging Logic
IQR = Q3 - Q1 | Bounds: [Q1 - 1.5*IQR, Q3 + 1.5*IQR]
Score_Outlier = min( (Count(Outlier Rows) / N) * 100 * 5, 100.0 )
4
2. Duplicate Detection
Identifies exact record duplicates across key business candidate columns (Customer_ID, Amount, Date).
Formula & Flagging Logic
Flagged Condition: Duplicated multi-column key tuples
Score_Duplicate = min( (Count(Duplicate Rows) / N) * 100 * 10, 100.0 )
3. Time-Series Analysis
Detects temporal volume spikes exceeding 2.5 standard deviations above the daily average.
Formula & Flagging Logic
Spike Threshold: Daily_Volume > Mean_Daily + 2.5 * StdDev_Daily
Score_TimeSeries = min( (Count(Spike Days) / Total Days) * 100 * 5, 100.0 )
4. Correlation Analysis
Identifies rows breaking strong linear relationships (|r| ≥ 0.8) using non-parametric Modified Z-scores.
Formula & Flagging Logic
Ratio_i = Col1_i / (Col2_i + 10^-5) | Modified Z_i = 0.6745 * |Ratio_i - Median(Ratio)| / MAD(Ratio)
Flagged Threshold: Modified Z_i > 4.0
Score_Correlation = min( (Count(Breakdown Rows) / N) * 100 * 5, 100.0 )
5. Benford's Law Test
Evaluates leading digit frequencies (1–9) in monetary columns against Benford's logarithmic distribution.
Formula & Flagging Logic
Expected: P(d) = log10(1 + 1/d) | MAD = Mean(|P_observed(d) - P_expected(d)|)
Flagged Threshold: Digits with P_observed(d) > 1.8 * P_expected(d)
Score_Benford = min( (MAD / 0.03) * 100, 100.0 )
5
6. Measure of Central Tendency
Detects extreme non-parametric skewness between Mean (μ) and Median (M) scaled by Standard
Deviation (σ).
Formula & Flagging Logic
Skewness = |μ - M| / σ | Flagged Condition: Rows with |x - μ| > 3*σ in columns where Skew > 0.5
Score_CentralTendency = min( Mean(Skewness_all_cols) * 100, 100.0 )
7. Measure of Dispersion
Evaluates statistical spread using Coefficient of Variation (CV = σ / |μ|).
Formula & Flagging Logic
Flagged Condition: Rows outside [Q1 - 2.0*IQR, Q3 + 2.0*IQR] in columns where CV > 1.5
Score_Dispersion = min( (Mean(CV_all_cols) / 2.0) * 100, 100.0 )
8. Largest Subset Test
Identifies categorical groups dominating a disproportionate share (> 40%) of transaction records.
Formula & Flagging Logic
Ratio_col = Max_Category_Count / N | Flagged Condition: All rows in category if Ratio > 0.40
Score_LargestSubset = min( Max(Ratio_all_cats) * 100, 100.0 )
9. Largest Growth Test
Tracks month-over-month (MoM) entity transaction volume surges exceeding 300% growth.
Formula & Flagging Logic
MoM_Growth = (Count_t - Count_t-1) / Count_t-1 | Flagged Condition: Entities with MoM_Growth >
3.0
Score_LargestGrowth = min( (Count(Spiking Entities) / Total Entities) * 100, 100.0 )

4. Multi-Phase Aggregation & Overlap Resolution
TrustLens cross-references unsupervised ML detections with rule-based forensic findings using formal
set operations:
• Phase 3 Flagged Set (S_P3): Indices of all rows where Score 1 ≥ 50.0.
• Phase 4 Flagged Set (S_P4): Union of all row indices flagged across executed Phase 4 modules (S_P4 =
S_Test1 ∪ S_Test2 ∪ ...).
• Overlapping Records (S_Overlap): Intersection between ML and rule sets (S_P3 ∩ S_P4).
• Newly Surfaced Records (S_Surfaced): Set difference representing records missed by Isolation Forest
but caught by rules (S_P4 \ S_P3).
